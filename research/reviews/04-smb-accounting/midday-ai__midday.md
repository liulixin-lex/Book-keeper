# midday-ai/midday

- 分类：04 小企业财务（银行同步、收件箱单据匹配、发票、时间跟踪）
- 语言 / 许可证 / 最近提交：TypeScript（Bun、Next.js、Supabase/Postgres、Drizzle、Trigger.dev 任务）/ AGPL-3.0 / 2026-06
- 审查范围：`packages/db/src/{queries/transaction-matching.ts,queries/inbox-matching.ts,utils/transaction-matching.ts,scripts/matching-eval-db.ts}`、`packages/{inbox,banking,accounting,import,categories,mcp-apps}`

## 定位

面向自由职业者/小团队的业务助手：银行流水同步、收件箱（邮件/上传的发票与收据）自动匹配到流水、发票、对账导出给会计软件（Xero/QuickBooks/Fortnox 等连接器）。

## 数据模型（与匹配相关）

- transactions（银行流水：名称、商户名、金额、币种、本位币金额、日期、分类、状态）；inbox（单据：名称、金额、币种、日期、类型 invoice/expense、附件）；
- **transaction_match_suggestions**：候选（inbox_id、transaction_id、confidence_score、各分项分数、match_type、状态 pending/confirmed/declined/unmatched、反馈时间）；
- 团队级校准数据（历史确认/拒绝统计、优化后的阈值）。

## 匹配算法（重点）

1. **候选召回**：Postgres `pg_trgm` 词相似度（阈值 0.3）+ 金额区间 + 日期窗口，在数据库中先筛候选。
2. **分项打分（0–1）**：
   - 名称：规范化（去公司后缀 inc/llc/ltd/gmbh…、域名提取）后的相似度，叠加**别名学习分**（同一对名称被确认 ≥2 次则 0.9）；
   - 金额：同币种按相对差分档（0%→1.0，≤1%→0.98，≤2%→0.95，≤5%→0.85，≤10%→0.6，≤20%→0.3，另有含税比例回退）；跨币种用本位币金额比较；
   - 日期：按单据类型的**非对称窗口**（发票通常早于付款、收据通常晚于扣款）；
   - 币种：完全相同 1.0，同一本位币 0.7，其他 0.3。
3. **加权合成**：名称 10、金额 30、日期 15、币种 5；跨币种且商户已知时把权重从金额移向日期（汇率噪声）。
4. **规则加成与惩罚**：金额精确 + 名称/日期达标时设置置信度下限（0.92 / 0.85 / 0.78）；名称完全不相关 ×0.55；日期过远 ×0.65；**历史拒绝惩罚**（近 90 天同一对被拒绝/取消匹配的加权）。
5. **阈值自校准**：用团队的确认/拒绝反馈搜索最优阈值（限制在 0.55–0.85，并与启发式阈值混合保证稳定）；自动匹配阈值更严格，可开关。
6. 候选按置信度排序，每个流水/单据只取最佳且不冲突的组合；离线评估脚本衡量匹配质量。

## 可借鉴

- [MY1] 召回（数据库粗筛）+ 精排（分项打分）两阶段匹配。
- [MY2] 分项分数（名称/金额/日期/币种）与权重、加成、惩罚全部显式化，结果保存分项分数便于解释。
- [MY3] 非对称日期窗口（按单据类型）。
- [MY4] 从人工确认/拒绝中学习：别名、拒绝惩罚、阈值自校准。
- [MY5] “建议”与“自动匹配”两级阈值。
- [MY6] 匹配质量离线评估脚本。

## 不采用 / 风险

- AGPL；金额为浮点；依赖 Supabase 与多个外部服务。

## 对新系统的启示

- 对账/匹配引擎：候选召回 → 打分（可配置权重）→ 全局分配（避免一对多冲突）→ 建议/自动两级阈值 → 人工确认/拒绝反馈回流（别名、惩罚、阈值）；
- 我们的场景：兑换记录 ↔ 卡网订单（面值+时间）、Stripe 结算 ↔ 银行入账、微信/支付宝付款 ↔ 上游充值，均可套用；
- 匹配结果保存 `scores` 明细与 `explain` 文本，供人和 AI 复核。
