## 定位

上传支付宝/微信/银行账单 → 自动转换为可审计的 Beancount 复式记账数据 → 在线 Fava 查看报表；提供映射模板市场、审核队列、周期对账任务、MCP。分类在本地完成，不调用大模型（隐私）。

## 数据模型

- **映射（maps）**：支出映射（关键字 → 收款方、支出科目、币种）、收入映射（关键字 → 付款方、收入科目）、资产映射（支付方式关键字 → 资产科目全称）；**映射模板**（类型、是否公开、是否官方、版本号、模板项含关键字/科目/对方/币种/标签路径）可共享与导入；
- **解析管道（translate）**：`ConvertToCSV → InitializeBill → PreFilter → Parse → PostFilter → Cache → Format → FileWriting`，每步统一错误收集；解析结果缓存（多级缓存：解析缓存 → 惰性解析 → 账本）；
- **支付宝退款对端科目**：退款行通过预扫描找到原支付行，沿用原单的科目，保证退款冲回到正确的费用科目；
- **跨账单去重**（entry_dedup_service）：按交易时间（原始行时间前 10 位）、金额等比较，跨多次上传的重叠账单去重；
- **审核队列**（entry_review_queue_service）：用户级统一审核队列（加锁），记录引用来源，引用失效自动剔除；
- **相似度**：BERT 向量相似度（带缓存）把新摘要映射到最接近的关键字；
- **周期对账任务（reconciliation）**：RecurringTask（循环规则原文 + 归一化 RRULE + 基准日期）生成 ScheduledTask（预期执行日、实际完成日、**账本对账日期 as_of**、对账条目、**差额分配条目**、撤销关系、状态）；条目匹配器把 Transaction / Pad / Balance 标准化后比较；余额计算服务；
- **MCP**：`get_ledger_context`、`run_bql`（只读 BQL 查询）、`read_ledger_file` 等工具 + prompts/resources，用户身份认证。

## 可借鉴

- [BT1] 关键字映射 + 映射模板（可版本化、可共享）——非技术用户也能维护分类规则。
- [BT2] 导入管道分步骤、统一错误收集、可缓存重放。
- [BT3] 退款沿用原单科目（预扫描原支付行）。
- [BT4] 跨多次上传的重叠账单去重。
- [BT5] 统一审核队列（待确认条目，跨来源）。
- [BT6] 周期对账任务：按 RRULE 生成“对账待办”，记录对账日期、对账条目、差额如何分配，并可撤销。
- [BT7] MCP 只读查询走 BQL（领域查询语言）。

## 不采用 / 风险

- 以 Beancount 文本为最终存储，与我们的数据库账本方向不同；BERT 模型依赖较重。

## 对新系统的启示

1. 规则引擎提供“简单模式（关键字映射）”与“高级模式（条件树）”两种编辑方式，并支持规则包导入导出（版本号）；
2. 导入管道 = 可组合步骤（解析、过滤、标准化、去重、匹配、分类、生成草稿），每步产出可检查的中间结果；
3. 周期对账待办（如每周核对各上游站余额、每日核对 Stripe 结算），完成时记录对账日期与差额处理；
4. MCP 提供受限只读查询能力（参数化查询，而非任意 SQL）。
