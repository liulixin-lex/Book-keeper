## 定位

半自动导入工具：从多个独立数据源获取“待处理交易”，与已有交易及彼此之间做匹配合并，预测未知科目，在 Web 界面逐条确认。

## 设计要点

- **多数据源插件**：OFX（银行/投资/退休账户）、Mint、Amazon 订单、Venmo，以及任意 beangulp 导入器；
- **来源关联元数据**：导入的交易与 posting 上写入来源标识（如 OFX 的 FITID、Amazon 订单号），数据源据此判断“已导入”，**天然防重复**；
- **cleared 约束**：来自权威来源的 posting 标记为 cleared，**一条 cleared posting 只能与 uncleared posting 匹配**（两个权威来源的同一笔不能互相合并），用来约束匹配；
- **匹配与合并**：对每笔待处理交易，同时在已有交易和其他待处理交易中找候选，计算若干“合并后交易”候选（例如银行扣款 + Amazon 订单明细合并成一笔带商品明细的交易），界面展示每个候选会新增/删除哪些行；
- **未知科目预测**：决策树分类器，训练数据来自已有交易上的来源元数据；
- 用户选择候选并确认/修改预测科目后写入日记账，自动进入下一条。

## 可借鉴

- [BI-1] 多来源交叉合并：同一业务在不同来源各有一条记录（如“微信付款”+“上游站兑换记录”+“卡网订单”），合并为一笔带全部证据的交易。
- [BI-2] 权威来源标记（cleared）约束匹配：来自同一权威来源的两条记录不能互相合并。
- [BI-3] 候选展示“将新增/删除哪些行”。
- [BI-4] 来源 ID 写入交易元数据作为去重依据。

## 对新系统的启示

1. 证据（evidence）模型：一笔交易可挂多条外部记录（订单、兑换、付款），每条外部记录只能被一笔交易“消耗”；
2. 匹配约束：同一来源类型的两条记录不得合并；匹配候选要说明依据；
3. 确认界面/接口返回 diff（新增分录、被冲正分录）。
