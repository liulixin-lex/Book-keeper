## 定位

为 OLTP 级金融交易设计的复式记账数据库：只有 Account 和 Transfer 两种对象，所有记录不可变，强一致、高吞吐，自带严格的余额约束。业务元数据放在外部“控制面”数据库。

## 数据模型

- **Account**：128 位 `id`、`ledger`（币种/资产分区号）、`code`（科目类型，如资产/负债/收入/支出及其子类）、`flags`、累计 `debits_posted / credits_posted / debits_pending / credits_pending`、三个可索引的 `user_data_128/64/32`、服务器时间戳。
- **Transfer**：`id`、`debit_account_id`、`credit_account_id`、`amount`（u128）、`ledger`、`code`（业务原因：购买/退款/换汇/更正……）、`pending_id`、`timeout`、`flags`、`user_data_*`。每笔只借一个、贷一个账户；多借多贷通过“链接事件”组合。
- **金额**：无符号 128 位整数；每个 ledger 约定一个 asset scale（如 USD=2，KWD=3），**资产精度一旦确定不可更改**（建议一开始就取足够大的精度）。
- **余额方向**：数据库只存累计借/贷，余额 = 借−贷（资产、费用）或 贷−借（负债、权益、收入），由应用按科目性质计算。
- `user_data` 约定：128 位存“谁/什么”（外部实体 ID）、64 位存“真实世界发生时间”（实现双时态）、32 位存“哪里”；`code` 存“为什么”。

## 记账逻辑与算法

- **余额约束标志**：`debits_must_not_exceed_credits` / `credits_must_not_exceed_debits` 保证账户不变负；“余额区间”配方用控制账户实现上下限。
- **两阶段转账**：pending（预留到 pending 字段）→ post（可部分过账，剩余释放）/ void / 超时自动作废。适合“已下单未到账”“已兑换未确认”等中间状态。
- **链接事件**：`flags.linked` 把一串转账绑定为原子单元，任一失败全部回滚；失败的第一笔返回具体错误，其余返回 `linked_event_failed`。
- **换汇**：不同币种分属不同 ledger，不能直接转；用两笔链接转账经“流动性账户”（L₁、L₂）完成，汇率隐含在两笔金额中；**点差/手续费单独记一笔**，而不是揉进汇率——这样事后能还原当时的汇率和费用。舍入偏向流动性账户以防套利。
- **更正**：转账不可修改/删除，“永远追加更多转账”；用专门的 `code` 标记更正原因，并复用 `user_data_128` 把更正与原交易关联。
- **余额条件转账、关闭账户、限流**等都通过组合转账 + 标志实现。

## 追溯与审计

- 全部对象不可变，时间戳由服务器单调分配；`flags.history` 账户保存余额历史，可查询任一时点余额。
- 更正链路完整保留“原错 → 更正 → 再更正”的时间线。

## API 与扩展

- 客户端批量请求（每批最多 8189 个事件），逐条返回结果码（`created`、`exists`、`exceeds_credits`……）。
- **可靠提交**：ID 由最上游客户端生成并先本地持久化再提交，重试用同一 ID；服务端返回 `exists` 视为成功——幂等由主键天然保证。
- 推荐时间有序 ID（48 位毫秒时间戳 + 80 位随机，同毫秒内递增），无需中心化发号。

## 可借鉴

- [T1] 科目性质决定余额方向，数据库只存累计借贷 —— 报表口径统一。
- [T2] 每个币种一个独立“账本分区”，跨币种必须通过换汇分录 —— 杜绝不同币种金额直接相加。
- [T3] 手续费/点差单独成分录，不混进汇率 —— 事后可还原汇率与费用（对应我们的 Stripe 手续费、卡网加价）。
- [T4] 两阶段（pending → post/void/expire）—— 表示“已付款未兑换”“已兑换未匹配订单”等在途状态。
- [T5] 链接事件 = 原子多腿交易，错误精确定位到第一条失败。
- [T6] 只追加更正 + 更正原因代码 + 关联 ID —— 完整更正时间线。
- [T7] 客户端生成时间有序 ID 作为幂等键，重试返回 `exists`。
- [T8] `code`（为什么）与 `user_data`（谁/何时/何地）的语义分工 —— 交易分类与外部实体关联的范式。
- [T9] 资产精度一次定好、取足够大。
- [T10] 余额约束（不得为负/区间）作为数据库级不变量。

## 不采用 / 风险

- 专用数据库 + 外部控制面的双库架构：运维成本高，小规模账本不需要。
- 单借单贷的转账粒度：会计分录展示需要“多借多贷合并成一张凭证”，应在上层建交易（凭证）实体。
- 没有元数据、科目表、期间、报表。

## 对新系统的启示

1. 账户表带“科目性质”（资产/负债/权益/收入/费用），余额方向由性质推导。
2. 多币种：每条分录记原币金额 + 原币精度；本位币金额是派生值，并单独记录汇率快照；换汇、手续费各自成腿。
3. 引入“在途/待匹配”状态（pending），支持部分核销。
4. 交易 ID 支持客户端生成（ULID/UUIDv7），作为幂等键；重复提交返回原结果。
5. 交易类型码（业务原因）与外部引用（订单号、兑换码）分字段存储，并建索引。
6. 账户可配置余额约束（如“钱包类账户不得为负”）。
