# hoophq/sequence（原 decimals/sequence）

- 分类：02 账本引擎
- 语言 / 许可证 / 最近提交：Clojure + DynamoDB / Apache-2.0 / 2026-07（代码基本停更，CI 维护）
- 审查范围：`README.md`、`src/decimals/{transactions,balances,crypto}.clj`、`docs/openapi.yaml`

## 定位

极简的不可变账本 API：多币种、多租户（按 API Key 区分租户），账户随用随建。

## 数据模型

- 每笔转账拆成两条记录（`:debit` 一条、`:credit` 一条），**每条记录内嵌该账户转账后的余额**；
- 每个 (账户, 币种) 的第一条记录是 `:genesis`（余额 0）；
- 记录 ID = 上一条余额记录内容的 MD5，形成**按账户的哈希链**，配合 DynamoDB 条件写入保证同一前驱只能被接一次（天然的乐观并发控制）。

## 记账逻辑与算法

- 余额 = 链尾记录的 `balance` 字段，查询 O(1)，不需要更新任何可变字段（“没有一个字段被 update”）。
- 并发写同一账户时，后到者因前驱哈希已被占用而失败重试。

## 追溯与审计

- 每个账户的记录链可逐条校验（哈希 + 余额递推），篡改任何一条都会断链。

## 导入、分类与对账 / API

- 无导入对账；REST API + 事件推送到 Segment 做分析。

## 可借鉴

- [SQ1] 分录行内嵌“过账后余额”，余额查询 O(1)，历史余额天然可得。
- [SQ2] 按账户的哈希链 + “前驱唯一”约束 = 防篡改 + 乐观并发。
- [SQ3] genesis 记录让每个账户链有确定起点。

## 不采用 / 风险

- MD5 不适合作防篡改哈希（应用 SHA-256）。
- 账户随用随建、无科目表；无报表；项目已停止功能开发。

## 对新系统的启示

- 分录表可存 `balance_after`（按账户+币种递推）并在写入时校验前驱版本；审计哈希链用 SHA-256 串联交易。
