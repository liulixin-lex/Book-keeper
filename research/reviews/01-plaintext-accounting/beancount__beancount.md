## 定位

用纯文本文件描述全部账务的“复式记账语言”：文件即数据库，加载时解析 → 插件变换 → 校验 → 报表/查询（BQL）。是严格性与可追溯性的标杆。

## 数据模型（指令 Directive，全部不可变）

- `Open`（账户开立日、**允许的币种列表**、该账户的成本匹配方法 booking）、`Close`（关闭后不可再记账）；
- `Commodity`（币种/商品声明及属性）、`Price`（某日价格/汇率）；
- `Transaction`：date、flag（`*` 已确认 / `!` 待核）、payee、narration、**tags（标签）与 links（关联号，把相关交易串起来，如同一订单的付款与退款）**、postings；
- `Posting`：account、units（数量+币种）、**cost（成本/批次，`{}`）**、**price（换算价，`@`）**、flag、meta；
- `Balance`（**余额断言**：某日开始时某账户某币种余额应为 X，可带容差）、`Pad`（自动用来源账户补平到下一个断言）；
- `Note`、`Document`（把文件挂到账户上）、`Event`（随时间变化的状态，如“所在城市”）、`Query`（命名查询）、`Custom`；
- 每个指令带 meta，自动包含 `filename`、`lineno`——任何数字都能定位到源头行。
- 账户名必须以五大类根开头：`Assets`、`Liabilities`、`Equity`、`Income`、`Expenses`（名称可配置）。

## 记账逻辑与算法

- **自动补全（interpolation）**：一笔交易最多一个 posting 可省略金额，由其余推算；按币种分别计算残差。
- **容差推断**：每个币种的容差 = 交易中出现的最小小数位的一半，涉及成本/价格时按倍数放大；可全局设置默认容差——解决“0.333×3≠1”这类舍入问题，同时不放过真实错误。
- **库存（Inventory）与批次**：持仓以 (币种, 成本, 购入日, 标签) 为批次；减少持仓时按账户的 booking 方法匹配：STRICT（歧义报错）、STRICT_WITH_SIZE、FIFO、LIFO、HIFO、AVERAGE（平均成本）、NONE（允许混合）——**可用于外币/额度的成本核算与汇兑损益**。
- **价格与汇率**：`@` 记录交易时的换算价并可由 `implicit_prices` 插件自动生成价格库；报表可按成本、按市值（指定日期的价格）换算。
- **余额断言**：日初余额必须等于断言值（容差内），否则报错——对账利器。
- **Pad**：在断言之前自动插入补平分录（常用于期初）。
- **期间汇总（summarize）**：把某日前的交易汇总为期初分录（clamp/close/open），用于年度结转与报表裁剪；`Equity:Conversions` 吸收多币种换算差额。

## 追溯与审计

- 每笔数据都有文件+行号；文本文件可放 Git 版本控制，完整历史 = git log。
- 校验：开闭户顺序、关闭后禁止记账、重复余额断言、重复商品、**币种约束（账户只允许声明的币种）**、交易平衡、数据类型、文档路径。

## 导入、分类与对账

- 导入由 beangulp（框架）负责；余额断言用于和银行对账单核对；`noduplicates` 插件按哈希防重复交易。

## API 与扩展

- **插件机制**：加载后、校验前对指令列表做变换或检查（如 `check_commodity` 所有币种必须声明、`leafonly` 只能记到叶子账户、`onecommodity` 账户单一币种、`check_closing` 关闭前余额必须为零、`sellgains` 卖出损益校验、`implicit_prices`、`auto_accounts`、`nounused`、`unique_prices`）。
- BQL（SQL 风格查询）；Python API。

## 可借鉴

- [BC1] 余额断言（某日某账户余额应为 X）+ 容差 —— 对账与防漏账核心机制（对应上游站余额、渠道余额、钱包余额核对）。
- [BC2] 账户声明允许的币种、开户/销户日期，越界报错。
- [BC3] tags + links：标签分类 + 关联号串联多笔相关交易（订单号、兑换批次、导入批次）。
- [BC4] 每条数据的来源定位（文件、行号）——新系统对应“来源凭证 + 行号/字段路径”。
- [BC5] 自动补全 + 按币种容差推断 —— 舍入有据可依。
- [BC6] 批次成本与 booking 方法（FIFO/AVERAGE…）—— 外币/上游额度成本核算。
- [BC7] 价格库 + 按成本/按市值/按日期换算的报表口径；`Equity:Conversions` 处理多币种换算差。
- [BC8] 插件式校验规则（可组合的不变量检查）。
- [BC9] flag（`*` / `!`）区分已确认与待核实。
- [BC10] 期间汇总/结转为期初分录。

## 不采用 / 风险

- 纯文本文件作为数据库：多人并发编辑、API 写入、权限控制都不方便；性能随文件增长下降。
- 只有日期没有时间（同日按文件顺序）——我们需要精确时间（兑换时间、付款时间）。
- GPL-2.0：只参考设计。

## 对新系统的启示

1. 引入“余额断言”实体：账户（含上游站虚拟账户）+ 日期 + 期望余额 + 来源（截图/对账单），系统自动比对并报告差异。
2. 账户级约束：允许币种、开户/销户日期、只允许叶子账户记账。
3. 交易支持 tags 与 links；导入批次、订单号、兑换码等作为 link 串联。
4. 每笔交易保存来源定位（凭证 ID + 行/字段）。
5. 校验规则做成可插拔的“不变量检查”列表，可在 API 中单独调用（如 `/checks/run`）。
6. 多币种：交易时的价格（@）与成本（{}）分开记录；报表支持按记账汇率与按指定日汇率两种口径。
