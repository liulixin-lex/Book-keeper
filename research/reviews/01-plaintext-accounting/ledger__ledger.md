# ledger/ledger（Ledger CLI）

- 分类：01 纯文本复式记账（开创者）
- 语言 / 许可证 / 最近提交：C++ / BSD-3-Clause / 2026-09-22
- 审查范围：`doc/ledger3.texi`（手册：Commodities、Metadata、Virtual postings、Balance verification、Costs vs prices、Lots、Automated/Periodic transactions、Effective dates、Value expressions）、`doc/GLOSSARY.md`、`src/`

## 定位

纯文本复式记账的鼻祖：日记账文件 + 强大的命令行报表与“值表达式”查询语言，强调“账永远是平的，但报表可以灵活变换”。

## 数据模型

- 交易：日期、**可选生效日（`日期=生效日`，交易级或 posting 级的辅助日期）**、状态（`*` cleared / `!` pending）、代码、收付款方、注释与**类型化元数据（`; Key: Value`，可声明类型）**、postings；
- Posting：账户、金额（商品可任意，包括时间、股票）、成本 `@`/`@@`、批次价格/日期/备注 `{}`/`[]`/`()`、余额断言/赋值；
- **虚拟 posting**：`(Account)` 不要求平衡（如预算跟踪），`[Account]` 要求虚拟部分自身平衡；报表可用 `--real` 排除；
- 商品价格历史（`P` 指令）、**商品等价关系（`C` 指令，如 1h = 60m，可用于“$1 额度 = ¥1”这类内部换算约定）**。

## 记账逻辑与算法

- 每笔交易必须平衡（虚拟 posting 除外）；
- **自动交易（`= 谓词`）**：任何 posting 匹配查询谓词时，自动追加一组 posting；支持**金额乘数**（如 `(Liabilities:Tax) 0.03` 表示匹配金额的 3%）、引用匹配 posting 的金额、读取当前账户余额——可用于按比例自动计手续费/税；
- **周期交易（`~ Monthly`）**：预算与预测；
- **生效日**：同一笔交易区分记账日与实际收付日（如开票日与回款日），报表可选按哪个日期；
- 成本与价格区分（成本固定在批次上，价格只是换算参考）；批次自动匹配；`--exchange`/`-X` 按价格历史换算到目标币种。
- 值表达式语言：用于查询、自定义报表列、自动交易谓词。

## 追溯与审计

- 文本 + 版本控制；`--strict`/`--pedantic` 要求账户、商品预先声明。

## 导入、分类与对账

- `convert` 命令（CSV 导入，基于历史交易猜测收付款方与账户）；余额断言。

## 可借鉴

- [LD1] 自动交易：谓词匹配 + 金额乘数（按比例生成手续费/税分录）。
- [LD2] 交易级/分录级生效日（记账日 vs 实际收付日）。
- [LD3] 商品等价关系（内部换算约定，如“上游额度 $1 = ¥1”作为显式规则而非硬编码）。
- [LD4] 虚拟 posting 用于预算/备忘跟踪，不污染真实账。
- [LD5] 类型化元数据（声明字段类型，查询时按类型比较）。
- [LD6] 成本（批次固定）与价格（换算参考）严格区分。

## 不采用 / 风险

- 不平衡的虚拟 posting 容易被滥用；新系统用“统计账户/备查簿”替代。
- 文本存储、CLI 交互，不适合多人协作与 API 写入。

## 对新系统的启示

- 交易模板中的手续费规则可表示为“匹配条件 + 比例乘数 + 目标科目”；
- 交易可带 `effective_date`（实际收付日），默认等于记账日；
- “额度兑换比例”（如 $1 额度 = ¥1）做成可配置的商品换算规则，并按生效期间管理。
