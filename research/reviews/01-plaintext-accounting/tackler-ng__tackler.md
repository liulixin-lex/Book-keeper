# tackler-ng/tackler

- 分类：01 纯文本复式记账
- 语言 / 许可证 / 最近提交：Rust / Apache-2.0 / 2026-10-17
- 审查范围：`README.adoc`、`tackler-api/src/metadata{,/items}.rs`、`tackler-core/src/config/items.rs`（audit 配置）、`docs/`

## 定位

高性能（>120 万笔/秒）纯文本记账引擎，主打**原生 Git 存储**与**会计审计**：报表可证明由哪一个确定的数据集生成。

## 数据模型

- 交易可带 UUID、地理位置（GIS）、标签、代码；账户、商品可强制预先声明（严格模式）；
- 日记账可直接从 Git 仓库的某个提交/引用读取（不需检出工作区）。

## 记账逻辑与算法

- 平衡校验、价格与市值（当前/历史/可变市值三种估值方法）、交易过滤器（账户、时间、描述、标签、金额、地理范围的组合布尔表达式）。

## 追溯与审计（重点）

- **审计模式**：每笔交易必须有 UUID；报表元数据中附带
  - **Txn Set Checksum**：参与本次报表的交易集合（按 UUID）的 SHA-512/256 哈希与条数；
  - Git 存储时附带提交 ID、引用名、提交信息；
  - 所用的交易过滤器定义。
- 效果：任何一份报表都能证明“由哪一版数据、哪些交易、哪个过滤条件”算出，可重复验证。
- 520 个跟踪的测试向量保证与旧版行为一致。

## 可借鉴

- [TK1] 报表附带“数据集指纹”（交易 ID 集合哈希 + 条数 + 数据版本 + 过滤条件）—— 报表可复算、可证明。
- [TK2] 交易强制带全局唯一 ID（审计模式）。
- [TK3] 交易过滤器是可序列化的表达式，随报表一起输出。
- [TK4] 用大量固定测试向量做回归。

## 不采用 / 风险

- Git 作为存储对多人在线编辑不友好；GIS 维度与本业务无关。

## 对新系统的启示

- 报表/导出接口在响应中附带 `dataset: {txn_count, txn_ids_sha256, as_of_event_seq, filters}`；
- 用“事件序号”作为数据版本，报表可指定 `as_of_seq` 精确复现；
- 建立会计计算的黄金测试集（输入交易 → 期望报表）。
