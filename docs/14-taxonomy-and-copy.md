# 14 分类体系与文案规范

> 本文是科目、收支分类、交易类型、渠道、往来方、标签、摘要与界面文案的**唯一标准**。其他文档中的示例与本文冲突时以本文为准。
> 依据：《小企业会计准则》科目编码；v1 实际业务数据的分类与往来方（具体数量见迁移报告，不写入文档）。

## 1. 原则

1. **一个概念一个名字**：同一事物在数据库、接口、界面、报表、文档中只用一个中文名和一个英文代码（见 §2）。
2. **科目管会计，维度管分析**：科目只表达会计性质（收入、成本、费用、资金）；渠道、站点、品牌等分析口径放在维度与往来方，不写进科目名称。
3. **按经济实质归类**：直接用于提供 API 服务的支出（上游额度、账号、AI 订阅、服务器与网络）一律计入主营业务成本；与服务交付无直接关系的支出计入期间费用。
4. **资金不细分**：微信、支付宝、银行卡与各平台余额统一记入“资金账户”，多币种并存，不按支付工具拆分。
5. **付款即成本**：上游额度在付款时确认成本，不设预付额度与消耗环节。
6. **摘要可读、可检索**：摘要按固定结构自动生成，不出现无意义字符，原始文本另存。

| 撤销 | undo | 撤回某次操作的全部写入 | 回滚 |

## 5. 交易类型

代码规则：英文 snake_case，`对象_动作` 或单一名词；名称为 2–6 个汉字的名词短语。

| 组 | 代码 | 名称 | 说明 | 生成的分录 |
|---|---|---|---|---|
| 收入 | `sale` | 销售收入 | 经销售渠道收到的 API 额度销售款；渠道扣除的手续费单独入账 | 借 资金账户（净额）、借 手续费；贷 API 额度销售（毛额） |
| 收入 | `sale_refund` | 销售退款 | 退还客户款项，关联原销售 | 原销售的反向，可选是否退回手续费 |

| 资金 | `transfer` | 资金划转 | 资金在科目或币种之间转移（含结汇、换汇），不影响损益 | 借 转入、贷 转出；跨币种自动生成兑换腿与汇兑损益 |

| 类别 | 规则 | 示例 |
|---|---|---|
| 上游站点 | **站点名 = 实际主机名**：小写，去掉协议、路径与端口，子域一个不剥（`api.`、`sub.`、`sub2.` 都是站点名的一部分）；品牌名、俗称作为别名。只有 `www.` 视为同一站点；同一主域下的其他主机是不同的站点，匹配按主机名精确比较 | `api.relay-a.example` → **api.relay-a.example**；`sub.relay-g.example` → **sub.relay-g.example**（别名 极光） |

## 9. 摘要规范

### 9.1 结构

```
<主体> · <业务> · <补充>
```

- 主体：往来方或渠道；业务：交易类型或收支分类；补充：订单号、面值、商品关键词等（可省略）；
- 分隔符为“ · ”（中点两侧各一个空格）；总长 ≤ 60 字；
- 不写金额（额度采购的面值除外）、不写日期（汇总交易除外）、不写表情与营销语；
- 品牌保持官方大小写；域名小写；订单号原样保留。

### 9.2 默认模板

| 交易类型 | 模板 | 示例 |
|---|---|---|
| `sale` | `{渠道} · API 额度销售[ · {订单号}]` | 链动 · API 额度销售 · LD260901EXAMPL |
| `sale_refund` | `{渠道} · 销售退款[ · {订单号}]` | Stripe · 销售退款 |
| `credit_purchase` | `{站点} · 额度采购 · 面值 {面值}[ · {渠道}]` | relay-b.example · 额度采购 · 面值 ¥50 · 链动 |
| `credit_purchase`（汇总） | `{站点} · 额度采购 · {日期} 合计 {笔数} 笔` | relay-c.example · 额度采购 · 2026-09-16 合计 5 笔 |
| `expense` | `{往来方} · {分类}[ · {商品关键词}]` | OpenAI · AI 服务订阅 · Pro 3；腾讯云 · 服务器与网络 · TDSQL-C MySQL；链动 · 账号 · 示例 Plus 成品号 |
| `purchase_refund` | `{往来方} · 采购退款[ · {原交易号}]` | |
| `transfer` | `{转出科目} → {转入科目}` / `结汇 · {原币} → {目标币}` | 结汇 · GBP → CNY |
| `opening_balance` | `期初余额 · {科目}` | |
| `manual_journal` | `调整 · {原因}` | 调整 · 补记 9 月汇率差 |

用户或 AI 填写的摘要只要符合 §9.1 即保留，并锁定该字段；不符合时接口返回警告 `DESCRIPTION_STYLE`（不阻止保存）。

往来方或渠道改名时，没有被手动改过（字段未锁定）的自动摘要随之更新：主体位置（往来方或渠道，按上表模板）与额度采购末尾的渠道换成新名字；手动写的摘要不动。

### 9.3 商品关键词清洗

从卡网商品标题生成“商品关键词”：去掉【】[]（）() 及其中内容 → 去掉表情与特殊符号 → 合并空白 → 保留前 20 个字符。原始标题存入 `metadata.original_title`。

| 原标题 | 关键词 |

### 10.3 报表名称

### 10.4 提示与错误文案

格式：`{做什么}失败：{原因}。{怎么办}`，例如：
- “修改失败：交易 T2026-000123 已删除。请先恢复再修改。”
- “导入失败：文件合计 1,234.56 与解析结果 1,230.00 不一致。请确认文件完整后重新上传。”

规则：说清对象与原因，给出下一步；不用“非法”“异常”等含糊词；金额带币种符号与千分位；日期用 `YYYY-MM-DD`。
