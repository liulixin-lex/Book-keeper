# 02 需求与范围

> **2026-10-19**：草稿、过账、复核、两段式预览、期间结账与锁账、期末重估、对账与核销等已去掉，本文相关内容仅作设计记录；现状见 [17 精简账本](17-lean-ledger.md)。

## 1. 目标

建设一套**逻辑严谨、数据齐全、分类清晰、记账方便、追溯方便**的复式记账后端（v2），并提供可供外部 AI 读取与编辑的 REST API 与 MCP 服务。前端在后端完成后另行设计。

## 2. 范围

### 2.1 包含

| 模块 | 说明 |
|---|---|
| 账套与基础数据 | 账套（本位币、时区、舍入策略）、商品/币种、汇率、价格规则、科目表、维度、往来方 |
| 业务录入与过账 | 交易类型、版本化过账模板、手续费规则、草稿 → 过账、冲正、更正、重过账 |
| 总账 | 不可变分录、连续编号、哈希链、余额与发生额、每日发生额表 |
| 期间 | 会计期间、软锁 / 硬锁、临时例外、结账检查与余额检查点 |
| 导入 | 来源定义、文件归档、解析器、标准化来源记录、安全校验、去重、增量水位线 |
| 规则 | 分类规则引擎（条件 / 动作 / 阶段 / 优先级），试运行、对历史执行、撤销 |
| 匹配与对账 | 记录 ↔ 交易、记录 ↔ 记录匹配；余额断言；对账会话；未清项核销；待核对款项；待办队列 |
| 报表与查询 | 三大报表、总账、明细账、试算平衡、维度分析、日报、手续费分析、账龄、受限聚合查询、导出 |
| 审计与完整性 | 审计事件、变更集、字段来源、健康检查、哈希链校验、报表指纹 |
| 外部接口 | REST API（OpenAPI 3.1）、MCP 服务（Streamable HTTP + stdio）、API 令牌、OAuth 2.1、Webhook |
| 运维 | 后台任务、备份恢复、监控日志、旧数据迁移 |

### 2.2 明确不包含

| 不包含 | 说明 |
|---|---|
| 内置 AI 模块 | 系统内不调用任何大模型或外部 AI 服务（含 OCR、自动识别、对话助手）。智能能力由外部 AI 通过 MCP 接入。系统内只有确定性规则，以及基于历史频次的推荐（可关闭）。 |
| 审批模块 | 没有审批流、待审批状态或审批人角色。写入权限由角色与令牌作用域决定；“预览 → 确认提交”是写入安全步骤，不是审批。 |
| 订阅管理 | 没有订阅 / 周期合约管理，也不在 v2.0 提供周期交易自动生成。软件订阅等支出按普通费用交易记录。 |
| 前端 | 本阶段只设计和实现后端；后端提供前端所需的 schema 与能力接口。 |
| 税务申报、工资、库存、发票开具 | 不在范围内。 |

## 3. 业务场景（必须覆盖）

以下场景来自实际业务数据（API 额度转售业务）。v2 的模板、手续费规则与导入器必须能完整表达这些场景，且不依赖旧系统的任何设计。

| 编号 | 场景 | 关键要求 |
|---|---|---|
| S1 | 渠道销售收入（卡网店铺代收） | 毛额、渠道按比例扣费（如 3%、1.8%）、净额进平台余额；订单号可追溯 |
| S2 | 结汇 | 外币收入（如 GBP）兑换为人民币；汇兑差额显式入账 |
| S3 | 外币收入（支付处理商，如 Stripe） | 原币毛额 / 手续费 / 净额；按日汇率折算本位币，也允许使用实际汇率；结算换汇时汇兑差额显式入账 |
| S4 | 上游额度采购 | 通过卡网购买兑换码或在站点自有商店购买；**付款即计入成本**；面值与实付不同（手续费内含或外加、赠送额度）；额度单位与本位币之间的换算约定；同一站点多个账号 |
| S5 | 兑换记录与采购订单互证 | 按“往来方 + 面值 + 时间最近”做全局最优匹配；未匹配时按往来方默认费率兜底，并标记为估算 |
| S6 | 一般费用 | 账号购买、云服务、软件订阅、其他；支持附件证据 |
| S7 | 资金划转 | 资金在科目之间转移（如存入保证金、借款收付），不进损益；微信、支付宝、银行卡与平台余额之间的转移不记账（统一为一个资金账户） |
| S8 | 退款 | 销售退款、采购退款，沿用原交易的科目与维度，并与原交易关联 |
| S9 | 赠送 / 零成本额度 | 可只记统计数量、不记金额，或按零成本入账；不得混入采购成本 |
| S10 | 日期归属 | 业务日期按账套时区（Asia/Shanghai）的自然日 00:00 切分；保留原始时间与时区偏移；日期精度可为日 / 月（历史数据） |
| S11 | 待确认数据 | 证据不完整（如仅有截图）时允许以草稿或待核对款项入账，并进入待办 |
| S12 | 规则追溯修正 | 手续费率或模板修正后，批量重算受影响交易，先预览差异，再生成调整，全程留痕 |
| S13 | 期末 | 平台余额、钱包余额对账；余额断言；待办清零；结账并生成检查点 |
| S14 | 外部 AI 记账 | 外部 AI 通过 MCP 查询、录入草稿、导入账单、分类、匹配、过账、冲正；所有写入可识别、可筛选、可撤回 |

## 4. 功能需求

编号规则：`FR-<模块>-<序号>`。优先级：P1 = v2.0 必须，P2 = v2.0 应有，P3 = 后续。

### 4.1 账套与基础数据（BASE）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-BASE-01 | 支持多账套；每个账套有本位币、时区、舍入模式、凭证字、默认科目表模板 | P1 |
| FR-BASE-02 | 商品表定义代码、名称、类别（法币 / 额度 / 其他）、精度、符号 | P1 |
| FR-BASE-03 | 汇率表记录对、日期、汇率、类型（参考 / 实际 / 派生）、来源、获取时间；支持按日自动获取与手工录入 | P1 |
| FR-BASE-04 | 价格规则表达固定换算约定（如 1 额度单位 = 1 CNY 名义价值），带生效区间 | P1 |
| FR-BASE-05 | 科目：编码层级、分组 / 明细、分类、正常方向、角色、允许商品、开户 / 销户日期、余额约束、是否允许手工、必填维度、国标代码、现金流活动 | P1 |
| FR-BASE-06 | 维度类型与维度值（如渠道、站点、项目），支持层级与停用 | P1 |
| FR-BASE-07 | 往来方：类型、别名与匹配模式、往来方下的子账户（如站点的多个账号）、默认交易类型 / 费率 | P1 |
| FR-BASE-08 | 基础数据变更有版本号，修改须提交期望版本 | P1 |

### 4.2 交易与过账（TXN）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-TXN-01 | 交易类型定义业务语义；每个类型有版本化过账模板（输入 schema、计算、分录行、校验） | P1 |
| FR-TXN-02 | 手续费规则：作用范围、生效区间、方法（比例 / 固定 / 取大 / 阶梯）、基数、内扣 / 外加、舍入、优先级、入账角色 | P1 |
| FR-TXN-03 | 交易状态：草稿 → 已过账；草稿可丢弃；已过账只能冲正 | P1 |
| FR-TXN-04 | 任何写入都支持 dry-run，返回将生成的分录、余额影响、警告与解释链 | P1 |
| FR-TXN-05 | 过账校验：各商品平衡、本位币平衡（尾差在容差内自动入尾差科目）、科目可记账、商品允许、开户期、维度必填、余额约束、期间锁、疑似重复 | P1 |
| FR-TXN-06 | 冲正：生成反向分录（可选原日期或指定日期），原交易标记已冲正，双向关联，原因必填 | P1 |
| FR-TXN-07 | 更正：冲正 + 新交易一步完成，互相引用 | P1 |
| FR-TXN-08 | 重过账：模板或费率规则变更后，选取受影响交易重算，预览差异，按策略生成调整或冲正重记 | P1 |
| FR-TXN-09 | 交易可关联多个来源记录、附件、标签、关联号（订单号、批次号） | P1 |
| FR-TXN-10 | 复核状态（未复核 / 已复核）独立于过账状态 | P1 |
| FR-TXN-11 | 字段来源与锁定：记录每个关键字段由谁设置，人工修改后锁定，规则与导入不得覆盖 | P1 |
| FR-TXN-12 | 批量创建 / 过账，支持“全部成功或全部失败”与“逐条报告”两种模式 | P1 |
| FR-TXN-13 | 手工凭证类型：直接录入分录行，受科目“允许手工”约束 | P1 |
| FR-TXN-14 | 统计数量：分录行可附带非货币数量（如额度单位数），用于分析，不影响平衡 | P1 |
| FR-TXN-15 | 录入辅助：按往来方历史频次推荐交易类型与科目；最近交易可作为模板复制 | P2 |

### 4.3 总账与期间（GL）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-GL-01 | 分录与分录行不可修改、不可删除（数据库强制） | P1 |
| FR-GL-02 | 凭证号按账套 × 凭证字 × 年月连续分配，过账时分配，可检测断号 | P1 |
| FR-GL-03 | 账套级分录哈希链，可校验 | P1 |
| FR-GL-04 | 余额表维护各科目 × 商品的余额与累计借贷；分录行记录过账后余额 | P1 |
| FR-GL-05 | 每日发生额表（科目 × 商品 × 业务日期），过账时同事务累加；任意日期余额 = 截至该日发生额之和 | P1 |
| FR-GL-06 | 会计期间（月）open → closed → locked；软锁日期、硬锁日期；临时例外（用户、截止时间、原因） | P1 |
| FR-GL-07 | 结账检查清单与余额检查点 | P1 |
| FR-GL-08 | 期末汇率重估凭证 | P2 |
| FR-GL-09 | 双时间查询：按业务日期，并可指定“截至某系统时间所知” | P2 |

### 4.4 导入（IMP）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-IMP-01 | 来源定义：类型、解析器与配置、默认科目与往来方、时区、去重策略、水位线 | P1 |
| FR-IMP-02 | 上传文件按 SHA-256 归档并去重，记录原始文件名、类型、大小 | P1 |
| FR-IMP-03 | 解析为标准化来源记录（外部 ID、时间、方向、金额、商品、对方、描述、订单号、原始数据） | P1 |
| FR-IMP-04 | 安全校验：合计核对、期初 + 明细 = 期末、期间覆盖、重叠检测；失败阻止提交 | P1 |
| FR-IMP-05 | 去重：外部 ID → 稳定指纹 → 模糊候选；负面规则；“不是重复”持久化 | P1 |
| FR-IMP-06 | 预览：每行的去重结果、规则命中、匹配候选、拟生成的交易与分录 | P1 |
| FR-IMP-07 | 提交生成草稿或直接过账（按来源配置与权限）；整批可撤销（未过账部分删除，已过账部分冲正） | P1 |
| FR-IMP-08 | 内置解析器：微信账单、支付宝账单、Stripe 余额流水、卡网订单列表（多店铺）、上游站点兑换 / 消费日志、通用 CSV / Excel（列映射） | P1 |
| FR-IMP-09 | 可保存的列映射配置；解析器有版本号与样例回归 | P1 |
| FR-IMP-10 | 逐行错误与警告报告 | P1 |

### 4.5 规则（RULE）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-RULE-01 | 规则：阶段（清洗 / 分类 / 过账前）、优先级、条件、动作、stop_processing、启用、版本 | P1 |
| FR-RULE-02 | 条件 AST 与查询 DSL 同源：字段比较、包含、正则（命名分组提取）、区间、约等、时段、星期、否定、全部 / 任一 | P1 |
| FR-RULE-03 | 动作：设交易类型、往来方、科目参数、维度、标签、描述、费率规则；拆分；忽略；标记待复核 | P1 |
| FR-RULE-04 | 规则试运行（对指定范围预览命中与变化）；对历史执行生成变更集，可撤销 | P1 |
| FR-RULE-05 | 命中统计与最近命中时间 | P1 |
| FR-RULE-06 | 从人工修正生成规则建议（不自动生效） | P2 |

### 4.6 匹配与对账（REC）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-REC-01 | 记录 ↔ 交易匹配：确定性多轮 + 打分；自动 / 建议双阈值；保存分项分数与方法 | P1 |
| FR-REC-02 | 记录 ↔ 记录匹配（多来源互证），支持 1:1、1:N、N:1，按键分组的全局最优指派 | P1 |
| FR-REC-03 | 未匹配记录跨批次持续参与匹配 | P1 |
| FR-REC-04 | 接受 / 拒绝建议；拒绝持久化，不再提示 | P1 |
| FR-REC-05 | 余额断言（科目、商品、日期、金额、容差、证据），检查失败进入待办 | P1 |
| FR-REC-06 | 对账会话：对账单期末余额、勾选分录、差额为零才可完成；完成后的勾选不可改 | P1 |
| FR-REC-07 | 未清项：指定科目的分录行维护未清余额，支持部分核销与撤销核销；外币核销产生汇兑差额 | P1 |
| FR-REC-08 | 待核对款项与统一待办队列 | P1 |
| FR-REC-09 | 匹配质量统计（自动匹配后被撤销比例等） | P2 |

### 4.7 报表与查询（RPT）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-RPT-01 | 试算平衡、资产负债表、利润表、现金流量表（间接 / 按活动分类） | P1 |
| FR-RPT-02 | 总账、明细账（含期初、发生、期末与逐行余额）、凭证列表 | P1 |
| FR-RPT-03 | 维度分析：按渠道、站点、往来方、交易类型、日 / 周 / 月分组 | P1 |
| FR-RPT-04 | 经营日报（按账套时区自然日）：收入、成本、手续费、净额 | P1 |
| FR-RPT-05 | 手续费分析、额度采购分析（数量、单价、按站点） | P1 |
| FR-RPT-06 | 未清项账龄、对账状态、待办统计 | P1 |
| FR-RPT-07 | 报表参数：期间、估值口径、目标币种、维度过滤、`as_known_at`；输出数据集指纹 | P1 |

| FR-RPT-09 | 导出：CSV、XLSX、Beancount 文本（可用第三方工具独立校验） | P1 |
| FR-RPT-10 | 保存报表快照（参数 + 指纹 + 结果） | P2 |

### 4.8 审计与完整性（AUD）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-AUD-01 | 每次写入记录审计事件：操作者、令牌、渠道、MCP 客户端、请求 ID、幂等键、变更集、前后值与差异、IP、UA | P1 |
| FR-AUD-02 | 审计事件哈希链 | P1 |
| FR-AUD-03 | 每个实体可查询变更历史 | P1 |
| FR-AUD-04 | 健康检查（约 20 项），可单独运行，结果入库；结账前强制通过 | P1 |
| FR-AUD-05 | 二分定位差异工具（找出首个不一致的日期） | P2 |
| FR-AUD-06 | 变更集：一次请求 / 工具调用 / 导入提交的全部写入归为一组，可整体撤销（草稿删除、已过账冲正） | P1 |

### 4.9 外部接口（EXT）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-EXT-01 | REST API 覆盖全部功能，OpenAPI 3.1 文档自动生成并纳入契约测试 | P1 |
| FR-EXT-02 | 写接口要求 `Idempotency-Key`；同键不同内容返回冲突 | P1 |
| FR-EXT-03 | 可变实体使用版本号乐观并发（`If-Match` 或 `expected_version`） | P1 |
| FR-EXT-04 | 统一错误格式（RFC 9457）含错误码、是否可重试、下一步建议、字段路径 | P1 |
| FR-EXT-05 | 列表：游标分页、过滤 DSL、排序、稀疏字段；增量同步（`updated_since`、分录序号） | P1 |
| FR-EXT-06 | MCP 服务：领域任务工具、资源、提示词；与 REST 共用服务层 | P1 |
| FR-EXT-07 | 令牌：作用域、只读默认、过期、吊销、最近使用、可选 IP 白名单；只存哈希 | P1 |
| FR-EXT-08 | MCP 高影响写入两段式（预览 → 提交，TTL）；所有写入支持 dry-run | P1 |
| FR-EXT-09 | MCP 调用日志；AI 写入自动标记来源，可筛选、可按变更集撤回 | P1 |
| FR-EXT-10 | OAuth 2.1（授权码 + PKCE、受保护资源元数据、动态客户端注册），供远程 MCP 客户端接入 | P2 |
| FR-EXT-11 | Webhook：事件订阅、HMAC 签名、重试与投递日志 | P2 |
| FR-EXT-12 | 字段级脱敏（凭据、联系方式等），返回 `redacted_fields` | P2 |

## 5. 非功能需求

| 编号 | 类别 | 要求 |
|---|---|---|
| NFR-01 | 正确性 | 任何时刻试算平衡（各商品与本位币）为零；所有不变量有数据库约束或触发器兜底，并有属性测试覆盖 |
| NFR-02 | 可追溯 | 任一报表数字可下钻到分录行 → 交易 → 来源记录 → 原始文件，反向亦然 |
| NFR-03 | 不可篡改 | 已过账数据只追加；哈希链每日校验，异常告警 |
| NFR-04 | 性能 | 规模按 100 万分录行设计；单笔过账 p95 < 100 ms；常用报表 p95 < 1 s；1 万行导入预览 < 30 s |
| NFR-05 | 可用性 | 单机部署；RPO ≤ 24 小时（每日备份 + 高风险操作前备份）；RTO ≤ 1 小时 |
| NFR-06 | 安全 | 密码 argon2id；令牌只存哈希；最小权限作用域；全站 HTTPS；审计认证事件；限流 |
| NFR-07 | 可维护 | 领域核心为纯函数模块，单元测试覆盖率 ≥ 95%；整体 ≥ 85%；类型检查严格模式 |
| NFR-08 | 可移植 | 数据可导出为开放格式（CSV / XLSX / Beancount）；附件按哈希存储，可直接拷贝 |
| NFR-09 | 本地化 | 界面文案与报表名称中文；接口字段英文 snake_case；时间统一 ISO 8601 带偏移 |
| NFR-10 | 兼容 | 接口版本化（`/api/v1`），破坏性变更需新版本 |

## 6. 术语

| 术语 | 含义 |
|---|---|
| 账套（book） | 独立的一套账，有自己的本位币、科目表与期间 |
| 商品（commodity） | 金额单位：法币（CNY、USD、GBP…）或非法币单位（如上游额度） |
| 交易（transaction） | 业务层记录：用户或 AI 录入的业务事实，按模板生成分录 |
| 分录（journal entry）/ 分录行（journal line） | 会计层事实，不可变，借贷平衡 |
| 过账模板（posting template） | 把交易输入转换为分录行的版本化规则 |
| 手续费规则（fee rule） | 计算手续费分量的版本化规则 |
| 来源（source）/ 来源记录（source record） | 外部数据渠道 / 从文件解析出的标准化行 |
| 匹配（match） | 来源记录与交易、来源记录之间、分录行之间的对应关系 |
| 待核对款项（suspense） | 暂未确定去向的金额所在科目（1999） |
| 未清项（open item） | 待核销的应收、应付、预付等分录行 |
| 变更集（change set） | 一次操作产生的全部写入，用于追溯与撤销 |
| 预览（preview） | 写入前的完整计算结果，可凭预览 ID 提交 |
