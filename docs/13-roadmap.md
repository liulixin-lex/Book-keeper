## M2 业务类型、手续费与业务报表（M）— ✅ 已完成（2026-10-18）
- 6 种业务类型由代码定义（不设模板引擎）：`sale`、`sale_refund`、`credit_purchase`、`expense`、`purchase_refund`、`transfer`；严格输入模型；科目 / 渠道 / 往来方 / 原交易接受编码、名称或 ID；往来方找不到时返回候选；
- 类型目录接口：输入 JSON Schema、默认科目、示例请求；
- 手续费规则：比例 + 固定额 + 上下限 + 币种，按类型 / 渠道 / 往来方 / 日期选择，版本化，`evaluate` 试算；实际值覆盖与偏差警告；估算标记；
- 自动摘要（14 号文档 §9.2），用户填写后保留；草稿部分修改；
- 退款继承原交易并校验累计不超额；`refund_of` / `correction_of` 双向关联；
- 更正（冲正 + 新交易，可只给变化的字段）；重过账（冲回重记，dry_run 预览）；解释链；
- 批量创建（原子 / 逐条）；检索：渠道、科目（含下级）、金额区间、估算、复核、关联交易；
- 结汇缺参考汇率时按实际兑换汇率折算；冲正行的统计数量随金额反向；
- 业务报表：概览、利润表（可逐期）、资产负债表、经营日报、销售分析、手续费分析、额度采购分析、通用汇总查询；每行带反查明细的 `drilldown`。

**实际结果**：测试 190 个全部通过，覆盖率 89%；05 号文档 §4.1 示例场景（销售、外币、额度采购、只知实付、结汇）均有用例。
**移出**：`fx_revaluation`、`year_end_close`、现金流量表 → M6（资产负债表已用“未结转损益”保证平衡）；模板引擎取消。

## 去除硬绑定（2026-10-19）

| 原来 | 现在 |
|---|---|
| 币种固定 6 个，新增需发版 | 币种是数据：REST / MCP 新增与停用；已有金额后小数位不可改（触发器保护）；法币自动获取参考汇率 |
| 手续费规则只用于销售与额度采购 | 也可用于费用支出、资金划转、销售退款（须在规则中列出）；实际录入优先 |
| 渠道只认代码 | 代码、名称、别名均可（链动 = liandong = 链动小铺），重名报错不猜测 |
| 每笔都要写渠道与类型 | 往来方默认交易类型与默认渠道自动带出（录入与导入），显式输入优先，回执标出 |
| 站点费率分散在规则里 | 往来方详情直接列出作用于该站点的手续费规则（仍是版本化规则，改费率不影响历史） |

文案：接口与错误信息中的“商品”（指币种）统一为“币种”，“导入记录”统一为“来源记录”，迁移报告不再用“异常”。

## v2.0 需求实现对照

02 号文档的 P1 需求均已实现并有测试，以下为按设计决定调整或暂缓的部分：

| 需求 | 实际 |
|---|---|
| FR-TXN-01 版本化过账模板 | 交易类型在代码中定义（M2 决定取消模板引擎）；输入 schema、默认科目与示例由类型目录提供 |
| FR-TXN-02 手续费方法 | 比例 + 固定额 + 下限（即“取大”）+ 上限，版本化与生效区间；阶梯费率未做（现有渠道均为单一比例） |
| FR-TXN-08 重过账策略 | 冲正重记（`repost_reversal` + `repost`），预览差额；不单独生成差额调整分录 |
| FR-RULE-03 规则动作 | 设类型、往来方、输入、渠道、分类、手续费、摘要、标签、忽略、待复核；“拆分”未做 |
| FR-REC-02 记录 ↔ 记录匹配 | 1:1 全局最优配对（含估算替换）；1:N / N:1 子集求和未做 |
| FR-REC-07 外币核销 | 按原币核销；本位币差额不在核销时结转，期末用汇率重估处理 |
| FR-RPT-01 现金流量表 | 直接法、按活动分类；间接法未做 |
| FR-RPT-07 报表参数 | 期间、维度过滤、`as_known_at`、数据集指纹已支持；估值口径 / 目标币种参数未做（外币敞口报表提供期末口径） |
| FR-EXT-05 列表 | 游标分页（交易、审计）与 `after_seq` 增量；具名过滤参数代替通用过滤 DSL；稀疏字段未做 |
| FR-AUD-04 健康检查 | 14 项检查 + 待办覆盖提示类事项（估算手续费、未处理记录、待确认匹配、失败断言） |
| FR-OPS-02 备份 | 每日备份、分级保留、每周恢复演练；“高风险操作前自动备份”改为发布与正式迁移前手动执行（应用容器不含数据库工具） |

验收（12 号文档 §5）：1 ✅（全部测试 236 个）；3 ✅（真实快照迁移到本地临时库后无 error 级检查）；4 ✅（09 号文档 §9 场景 A–D 以 MCP 回放测试通过）；6 ✅（基准）；2 与 5 需在服务器上执行（生产快照正式迁移、恢复演练），待用户确认后进行。

## 风险与对策

| 风险 | 对策 |
|---|---|
| 解析器依赖外部格式（卡网、上游站点日志格式不统一且会变） | `generic_tabular` + 可保存列映射兜底；解析器版本化与样例回归；安全校验阻止错误数据入账 |
| 手续费口径在历史上多次调整 | 规则版本 + 生效区间 + 重过账；迁移时以实际金额为准，不追溯重算 |
| 旧数据摘要无意义、往来方命名不统一 | 迁移时按 14 号文档重写摘要与往来方名称，原文保存在 `metadata.legacy` |
| AI 误操作 | 默认只读、最小 scope、两段式、来源标记、变更集撤回、审计 |
| PostgreSQL 引入运维成本 | Compose 托管、每日备份与每周自动恢复演练、迁移账号与应用账号分离 |
| 范围膨胀 | 严格按 P1 / P2 / P3 优先级；不包含 AI、审批、订阅模块 |
