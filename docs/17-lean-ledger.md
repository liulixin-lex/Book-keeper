# 17 精简账本（2026-10-19）

> 本文记录一次范围收缩，**优先于** 01–09、13 中与之冲突的描述。接口以 16 号文档（由代码生成）为准。

## 1. 为什么收缩

用户的定位（2026-10-19）：账本主要自用，用来统计中转站的经营数据；草稿、过账、复核这类兜底流程完全没必要，前后端不需要的模块都去掉。

原设计按多人记账、审计与结账来做：草稿 → 过账两步、复核标记、两段式预览、期间结账与锁账、年末结转与汇率重估、对账会话、余额断言、往来核销与账龄、资产负债表与现金流量表。对一个人记自己的经营账来说，这些步骤只增加操作，不增加信息。

## 2. 去掉的功能

| 功能 | 处理 |
|---|---|
| 草稿与单独的“过账”步骤 | 删除。记账即入账 |
| 更正（冲正后另开一笔新交易） | 删除。改为在原交易上修改，编号不变（§3） |
| 复核标记（`review_status`）与 `mark_review` 规则动作 | 删除 |
| 两段式预览（`previews`、`PREVIEW_REQUIRED`、`commit_preview`、令牌的 `require_preview_for`） | 删除。试算仍可用 `dry_run` |
| 期间结账、锁账、锁账例外、余额检查点、结账检查清单 | 删除。所有业务日期都可写入 |
| 期末汇率重估、年末结转 | 删除（`fx_revaluation`、`year_end_close` 交易类型停用） |
| 对账会话、勾对状态、余额断言、往来核销与账龄 | 删除 |
| 资产负债表、现金流量表、外币敞口、变更报告、未清项账龄、对账状态、总账、科目明细账 | 删除。保留：概览、利润表、经营日报、销售分析、手续费分析、额度采购分析、试算平衡表、自定义汇总 |

保留：业务类型与手续费规则、多币种与汇兑、导入（解析、去重、规则、匹配、配对）、标签、导出与月度存档、MCP、OAuth、审计与变更集撤销、健康检查。

## 3. 交易的生命周期

只有两种状态：`posted`（已入账）与 `reversed`（已删除）。

| 动作 | 效果 | REST | MCP |
|---|---|---|---|
| 记账 | 构建分录并立即入账 | `POST /transactions` | `create_transaction` |
| 修改 | 摘要、备注、标签、订单号、外部单号、元数据原地修改；日期、往来方、业务输入、分录行等影响账面的修改会重建分录，若与当前分录不同，则冲销当前分录（`repost_reversal`）并入账新分录（`repost`），交易编号不变 | `PATCH /transactions/{ref}` | `update_transaction` |
| 删除 | 冲销当前分录（`reversal`），交易从列表与统计中消失 | `DELETE /transactions/{ref}` | `delete_transaction` |
| 恢复 | 按删除前的分录重新入账 | `POST /transactions/{ref}:restore` | `restore_transaction` |
| 撤销 | 撤回某次请求的全部写入：新记的删除、删除的恢复、修改的改回（按当时的分录原样重记，不按新规则重算） | `POST /change-sets/{id}:undo` | `undo_change_set` |
| 按新规则重算 | 手续费规则或汇率修正后重建分录，变化的才冲销重记 | `POST /transactions:repost` | `repost_transactions` |

每个写入都可先 `?dry_run=true`（MCP：`dry_run=true`）查看完整结果，再正式执行。`expected_version` 可选，给出时防止覆盖他人的修改。删除与撤销的原因均为可选。

分录仍然只追加：数据库触发器禁止修改或删除分录与分录行，哈希链、幂等键与审计链不变。界面上的“编辑”“删除”在账本里都是追加的冲销与重记，所以总能撤回。

## 4. 权限

`ledger:draft`、`ledger:post`、`ledger:correct` 合并为 `ledger:write`；`periods:manage`、`reconcile:write` 取消。现有令牌在迁移时自动换算。

2026-10-19 后令牌预设改为四个档位（用户只读 / 用户读写 / 管理员只读 / 管理员读写），见 08 号 §3.3 与迁移 0014。

## 5. 统计口径

报表与自定义汇总默认只计每笔交易的**当前分录**：已删除的交易、修改前的旧分录都不出现（金额与把冲销相抵后的结果相同，只是不再留下净额为 0 的行）。给出 `as_known_at` 时按“当时已记录的全部分录”计算，冲销照常相抵，用于回看历史时点。

## 6. 数据库迁移 0011

- 草稿与已作废的草稿从未进入总账：删除，其来源记录回到待处理（已分类 / 待处理）。
- 删除表：`previews`、`lock_settings`、`lock_exceptions`、`period_checkpoints`、`fiscal_periods`、`reconciliations`、`line_matches`、`balance_assertions`。
- 删除列：`transactions` 的复核、更正与作废字段；`journal_lines` 的勾对与未清字段；`journal_entries.period_id`；`accounts.is_open_item`、`is_reconcilable`、`cash_flow_activity`；`api_tokens.require_preview_for`；`mcp_calls.preview_id`。
- 分录写入触发器只保留“以数据库时间为记录时间”；分录行改为完全不可修改。
- 令牌作用域换算；来源配置去掉 `commit_mode`；规则去掉 `mark_review`；停用期末系统交易类型。
- 单向迁移：回退请恢复迁移前的备份。真实数据试迁移：交易与分录全部迁移，哈希链校验通过；健康检查除 `normal_side`（原有数据的余额方向提示，与本次迁移无关）外全部通过。

## 7. 前端（2026-10-19）

Web 前端按精简后的接口重做为五个模块：概览、交易、统计、导入、设置（详见 v2/README.md “前端”，视觉规范见 `DESIGN.md`）。界面上没有过账、复核或确认对话框：记一笔、修改、删除、恢复、完成导入都立即生效，提示条上带“撤销”（撤回对应的变更集）；交易详情的“历史”按 记一笔 / 修改 / 删除 / 恢复 列出每次变动，背后仍是追加的分录。

## 8. 随前端一起的接口调整

- `GET /transactions?type=` 可用逗号给出多个类型（如 `sale_refund,purchase_refund`），MCP `search_transactions` 同义。
- 已完成导入的批次里留下的记录（缺字段或等待匹配），补全分类后立即入账（需 `ledger:write`，否则保持“已分类”）；入账失败时错误记在记录上，分类照常保存。
- 批次列表（REST 与 MCP）每批带 `open_records`：尚未入账的记录数（新批次里待补全或已补全、等完成导入的记录，以及已完成批次留下的未入账记录；已忽略、重复、已入账的不计）。前端的“待入账”数字都取自这里。
- 交易类型的示例（`GET /transaction-types` 的 `example`）去掉了已废弃的 `post` 字段，可原样提交；新增单元测试保证示例都能通过校验。

## 9. 导入增强（2026-10-19）

详见 06 号文档 §0.1、§0.2。

- 新来源类型：`redeem_page`（中转站兑换码页面打印的 PDF，本地读文字层）与 `ai_extract`（截图 / PDF 由 Claude 在后台读取，批次先显示“识别中”）。AI 识别需服务器配置 `BK_AI_API_KEY`，文件从服务器发到 Anthropic；配置、超时与成本控制见 15 号文档 §3.1。
- 已经记过的交易：导入时同类型、同一方、同一天的记录先与账上交易比对，单条相等或当天几条之和（最多 20 条子集求和）等于已记的合计就自动关联为凭证；对不上但可能是同一笔的，按交易分组，每组问一次“是同一笔 / 不是，单独入账”。写了往来方但账上没有这个往来方的记录直接按新记录处理，不打扰。
- 手续费依据可见：识别结果与交易详情都标出手续费按实际、按哪条规则，或“无手续费规则（按 0）”。费率与忽略名单只放在设置里（不写进代码或迁移），改了规则用“按新规则重算”。
- 设置新来源时可用样例文件试读列映射（`import-sources:preview`）。
- 数据库迁移 0012：来源类型与批次状态的 CHECK 约束增加上述值，不动数据，可回退。
