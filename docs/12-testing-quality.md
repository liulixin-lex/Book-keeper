## 2. 属性测试清单

| 编号 | 属性 |
|---|---|
| P-01 | 任意合法模板 + 输入构建的分录：各商品 Σamount = 0 且 Σbase_amount = 0 |
| P-02 | 拆分：Σ 份额 = 原金额；每份 ≥ 0；与理论值之差 < 1 个最小单位 |
| P-03 | 手续费 `included` 反算：base + fee = total；`added`：total − fee = base |
| P-04 | 删除：原分录 + 冲销分录的净额在所有科目 × 商品上为 0 |
| P-05 | 重算幂等：规则未变时按新规则重算不产生分录；修改后内容不变时不产生分录 |
| P-06 | 重算与修改正确：之后的当前分录 = 用新规则 / 新输入从头构建的行集 |
| P-07 | 撤销变更集：撤销后报表（除审计与冲销痕迹外）与变更前一致 |
| P-08 | 余额缓存：任意顺序（含回溯日期）记账、修改、删除后，`account_balances` 与 `daily_balances` = 由分录行重算 |
| P-09 | 哈希链：任意修改一行内容都会使校验在该 seq 失败 |
| P-10 | 去重指纹：同一文件重复导入不产生新记录；行顺序变化不影响指纹集合 |
| P-11 | 一维指派：DP 结果总代价 ≤ 任意贪心或随机可行匹配的总代价；与小规模穷举结果相同 |
| P-12 | 过滤 DSL：文本语法编译后的 AST 与等价 JSON AST 查询结果相同 |
| P-13 | 金额：任何路径都不出现 `float`（运行时类型检查 + 静态扫描） |
| P-14 | 幂等：同键同内容的 N 次并发请求只产生一次写入 |

## 3. 静态检查与规范

- ruff（含禁止 `float` 用于金额的自定义规则、禁止 `datetime.now()` 无时区）、ruff format；
- mypy：`domain/` 严格模式，其余标准模式；
- Alembic：每个迁移有升级测试（空库升级到最新、上一版本升级到最新）；不可逆迁移需显式声明；
- OpenAPI 快照对比（破坏性变更检测）；MCP 工具 schema 快照对比；
- 提交前钩子：ruff、mypy、单元测试。

## 4. CI 流水线

```
lint/format → type check → unit + property（固定种子）→ 启动 PostgreSQL →
integration → API（含 schemathesis）→ MCP → importers golden → reports golden →
Beancount 导出 + bean-check（隔离环境）→ 迁移测试（脱敏快照）→ 构建镜像 → 镜像扫描
夜间：property（随机种子，5000 例）+ 性能基准 + 依赖审计
```

## 5. 验收标准（v2.0 发布前）

1. 02 号文档全部 P1 需求有对应测试并通过；
2. 生产数据迁移 V1–V10 全部通过，用户确认核对报告；
3. 健康检查在迁移后的账套上无 error；
4. MCP 场景回放（09 号文档 §9 的 A–D）在预发布环境通过；
5. 备份恢复演练成功（恢复后检查通过）；
6. 性能基准满足 NFR-04。
