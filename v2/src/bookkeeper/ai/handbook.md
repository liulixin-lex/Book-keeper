# 识别规则手册

## 通用
- 只抄写页面上完整可见的金额行；被截断、看不清的行写进 unreadable，不猜。
- 时间用每一行自己的时间，不用截图或打印时间。页面没写年份时只写月日（如 --10-05 12:00:00），由系统按上传日期推断年份。
- 金额写成不带符号、不带千分位的小数；币种按符号判断：¥ / ￥ / 元 = CNY，$ = USD，£ = GBP，其他照写代码，看不出就留空。
- 订单号、交易号、兑换码逐字照抄，不补全、不改大小写。
- 站点写实际主机名：小写，去掉协议、路径和端口，子域名一个都不去（api.example.com 不能写成 example.com），只有 www. 可以视为同一站点。
- 不要从余额、累计用量反推金额；页面上的“共 N 条”“合计”“余额”只写进 totals。
- 状态照抄（已完成、已退款、支付失败、待支付…）。失败、未支付、已关闭的订单不是一笔钱，但仍然抄下来，由规则忽略。

## 页面类型
- 订单列表（order_list）：卡网、商城的订单页。我方是卖家（店铺后台、收到货款）方向为 in；我方是买家（买家订单查询、付款）方向为 out。商品标题写进 description，平台名（如卡网平台的名字）写进 channel。
- 充值与兑换记录（topup_log）：上游站点的充值、兑换码、余额变动日志。到账的额度写进 amount（单位照页面），实际付款金额另写 paid；兑换码或订单号写进 order_no；付款方式（兑换码、支付宝、站内商店…）写进 method。消费、调用日志不是钱，不抄。
- 钱包与银行流水（wallet_bill）：支付宝、微信、银行卡、Stripe、PayPal 等账单。收入为 in，支出为 out，转账给自己或理财划转为 neutral；手续费单独写 fee。
- 收据与订阅账单（receipt）：发票、订阅扣费、云服务账单。一般为 out；退款收据为 in。服务商写进 counterparty，计费项目写进 description。
- 其他（other）：以上都不是时用，照通用规则抄写。

## 分类
- 交易类型按经济实质：经销售渠道收到的 API 额度销售款是“销售收入”；向上游站点买 API 额度（站内充值、买兑换码）是“额度采购”；其他支出是“费用支出”，按分类选科目；退款对应“销售退款”或“采购退款”；自己的账户之间转钱是“资金划转”。
- 直接用于提供 API 服务的支出（账号、AI 服务订阅、服务器与网络）属于主营业务成本对应的分类；广告、注册办公、软件工具属于期间费用；都不适用时用“其他管理费用”。
- 往来方只用账套里已有的名字（含别名）；对不上就留空，不新造。渠道同理，只用账套里已有的渠道。
- 手续费由手续费规则自动计算，不要自己估算。
- 金额为 0、赠送、免费的记录建议忽略，并写明原因。
- 拿不准就降低把握程度并写明理由，交给用户确认，不要硬选。
